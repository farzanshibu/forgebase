# forgebase_function (Resource)

A serverless function: a JavaScript or TypeScript module, or a WebAssembly module. Every change to the code or configuration deploys a new version and activates it. The provider hashes the code (`content_sha256`) so a changed file shows in the plan, and a version changed outside Terraform shows as drift.

## Example Usage

```terraform
resource "forgebase_function" "hello" {
  name         = "hello"
  language     = "typescript"
  source_file  = "${path.module}/functions/hello.ts" # content changes are detected by hash
  description  = "Says hello"
  access       = "authenticated"
  capabilities = ["log", "env", "secrets"]

  env = {
    GREETING = "hello"
  }

  # Sensitive. The server never returns values, so only the presence of each
  # name is checked for drift; change a value to rotate it.
  secrets = {
    API_TOKEN = var.api_token
  }

  limits = {
    timeout_ms = 2000
  }
}

# A WebAssembly module, hooked to record changes.
resource "forgebase_function" "audit" {
  name         = "audit"
  wasm_file    = "${path.module}/functions/audit.wasm"
  capabilities = ["db.write", "log"]

  hooks = [
    { collection = "posts", events = ["after_create", "after_update"] },
  ]
}

variable "api_token" {
  type      = string
  sensitive = true
}
```

## Schema

### Required

- `name` (String) Function name: 1-48 characters, a lower-case letter, then lower-case letters, digits, `_` or `-`. Cannot change.

### Optional

- `access` (String) Who may invoke the function over HTTP: `public`, `authenticated` or `permission` (default).
- `capabilities` (Set of String) Granted capabilities: `db.read`, `db.write`, `kv`, `log`, `env`, `secrets`, `fetch`, `vector.read`, `vector.write`, `storage.read`, `storage.write`, `queues.publish`, `jobs.enqueue`, `realtime.publish`, `service_role`.
- `description` (String) Description.
- `env` (Map of String) Plain (non-secret) environment values, readable with the `env` capability. Use `secrets` for credentials.
- `fetch_hosts` (Set of String) Hosts the function may call with `fetch` (needs the `fetch` capability).
- `hooks` (Attributes List) Record hooks: run the function around record changes of a collection. (see [below for nested schema](#nestedatt--hooks))
- `kv_rules` (Attributes Set) Key-value namespaces a JavaScript function may reach (deny by default; needs the `kv` capability and an administrator credential). (see [below for nested schema](#nestedatt--kv_rules))
- `language` (String) `typescript` (default for `source`), `javascript` or `wasm` (implied by `wasm_file`).
- `limits` (Attributes) Resource limits. Unset values use the server defaults. (see [below for nested schema](#nestedatt--limits))
- `secrets` (Map of String, Sensitive) Secret values by name, readable with the `secrets` capability. The server never returns values, so only the presence of each name is checked for drift; to rotate a secret, change its value. Secrets not listed here are left alone, except those this resource set earlier and no longer lists, which are deleted.
- `source` (String) Inline JavaScript/TypeScript source of a single-file ES module that calls `serve()` from `"forgebase"` (at most 1 MiB). Exactly one of `source`, `source_file` and `wasm_file`.
- `source_file` (String) Path to the JavaScript/TypeScript source file, read when planning and applying. Changes to the file's content are detected by hash.
- `wasm_file` (String) Path to a compiled WebAssembly module, read when planning and applying. Changes to the file's content are detected by hash.

### Read-Only

- `active_version` (Number) Version currently active.
- `content_sha256` (String) SHA-256 (hex) of the source text or WebAssembly bytes. Compared with the active version on the server to detect drift.
- `created_at` (String) Creation time.
- `id` (String) The function name.
- `latest_version` (Number) Newest deployed version.
- `principal` (String) Identity the function runs as.
- `updated_at` (String) Last change.
