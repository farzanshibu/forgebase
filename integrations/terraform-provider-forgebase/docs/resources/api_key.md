# forgebase_api_key (Resource)

An API key of a service account. The key secret (`key`) is returned by the server once, at creation, and is kept in state as a sensitive value; it cannot be read back or recovered later, so an imported key has no `key`. Keys cannot be changed: every change creates a new key and revokes the old one. A key revoked outside Terraform is dropped from state, so the next apply issues a new one.

## Example Usage

```terraform
resource "forgebase_api_key" "deploy" {
  service_account_id = forgebase_service_account.ci.id
  name               = "deploy"
  scopes             = ["collections:write", "storage:write", "functions:write"]
  expires_in_days    = 90
}

# The secret is only known when Terraform created the key.
output "deploy_key" {
  value     = forgebase_api_key.deploy.key
  sensitive = true
}
```

## Schema

### Required

- `name` (String) Key name (1-100 printable characters).
- `scopes` (Set of String) Scopes narrowing what the key may do: `*`, `<area>:*`, `<area>:read`, `<area>:write`, or `<area>:read|write:<name>`. `write` does not imply `read`.
- `service_account_id` (String) Id of the owning service account.

### Optional

- `expires_in_days` (Number) Lifetime in days (1-3650). Omit for a key that does not expire.
- `tenant` (String) Bind the key to one tenant (environment id).

### Read-Only

- `created_at` (String) Creation time.
- `expires_at` (String) Expiry time, if the key expires.
- `id` (String) Key id (also visible inside the key).
- `key` (String, Sensitive) The key secret (`fbk_…`). Only known when Terraform created the key.


## Import

Import is supported using the following syntax:

```shell
# <service_account_id>/<key_id>. The key secret cannot be recovered: key stays null.
terraform import forgebase_api_key.deploy bupwgg8agu2l1fq/j2qnalhgyp764bon
```
