# forgebase_collection (Resource)

A ForgeBase collection: a typed table (`base`), a user table (`auth`) or a read-only SQL view (`view`). Changing `fields` applies transactional DDL on the server and is refused when existing data does not fit.

## Example Usage

```terraform
resource "forgebase_collection" "posts" {
  name = "posts"

  fields = [
    {
      name     = "title"
      type     = "text"
      required = true
      options  = jsonencode({ max_length = 200 })
    },
    {
      name    = "status"
      type    = "select"
      options = jsonencode({ values = ["draft", "live"] })
      default = jsonencode("draft")
    },
    {
      name = "published_at"
      type = "date"
    },
  ]
}

# A read-only view over a SQL query.
resource "forgebase_collection" "live_posts" {
  name       = "live_posts"
  type       = "view"
  view_query = "SELECT id, title FROM posts WHERE status = 'live'"

  depends_on = [forgebase_collection.posts]
}
```

## Schema

### Required

- `name` (String) Collection name (1-63 letters, digits or underscores, starting with a letter). Renaming is applied in place.

### Optional

- `fields` (Attributes List) Declared fields in order. Omit for `view` collections (their fields come from the query). Auth collections get their system fields (email, password, …) automatically; declare one only to tune it. (see [below for nested schema](#nestedatt--fields))
- `schema_mode` (String) `strict` (default) accepts declared fields only; `flexible` keeps other top-level keys as a JSON document.
- `tenant_scoped` (Boolean) Rows belong to tenants (environments) and are isolated per tenant. Cannot change after creation.
- `type` (String) `base` (default), `auth` (adds the account fields) or `view` (read-only, needs `view_query`). Cannot change after creation.
- `versioned` (Boolean) Keep every version of every record.
- `view_query` (String) The single `SELECT` statement of a `view` collection. Not allowed for other types.

### Read-Only

- `created` (String) Creation time.
- `id` (String) Server-assigned collection id.
- `updated` (String) Last schema change.
- `version` (Number) Schema version; increases with every change.

### Nested Schema for `fields`

### Required

- `name` (String) Field name (1-63 letters, digits or underscores, starting with a letter; `id`, `created`, `updated`, `expand` and names starting with `_` are reserved).
- `type` (String) One of: text, number, bool, date, email, url, select, json, array, relation, file, password, geo, vector.

### Optional

- `default` (String) Default value as a JSON document, e.g. `jsonencode(false)` or `jsonencode("draft")`.
- `hidden` (Boolean) Never returned by the API to non-privileged callers.
- `options` (String) Type-specific options as a JSON object, e.g. `jsonencode({ max_length = 200 })` for text, `{ values = ["a","b"], max_select = 1 }` for select, `{ collection_id = "…" }` for relation, `{ dimensions = 384 }` for vector. Only the keys you set are tracked, so server defaults do not show as drift.
- `renamed_from` (String) Previous name of this field. Set it in the same change that renames the field to keep the field's data (the server matches by id, and this tells the provider which existing field it is).
- `required` (Boolean) A value is required.
- `unique` (Boolean) Values are unique.

### Read-Only

- `id` (String) Stable field id; kept across renames.
