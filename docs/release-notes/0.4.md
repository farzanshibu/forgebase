# ForgeBase 0.4 release notes

## 0.4.0

A feature release built from the 2026-11 roadmap. Every new subsystem is off or unchanged by default.
Upgrading needs no configuration changes. Startup applies migrations 0050–0066 on both backends; take a
snapshot first, as for every upgrade ([operations/upgrades.md](../operations/upgrades.md)).

### Operations and reliability

- **Native TLS** ([ADR-0033](../adr/0033-native-tls-acme.md)): `[tls] mode = "off" | "files" | "acme"`. Certificate files
  are reloaded when they change or on SIGHUP. ACME supports tls-alpn-01 and http-01, any RFC 8555 CA (Let's
  Encrypt by default) and External Account Binding, and renews at two thirds of the lifetime. Also optional
  HSTS, a port-80 redirect, TLS for the Redis protocol (`[resp] tls`), an expiry warning in `doctor` and
  certificate metrics. Plain HTTP behind a proxy stays the default.
- **Tracing, alerts and SLOs** ([ADR-0035](../adr/0035-tracing-alerting-slos.md)):
  - OTLP/HTTP export of traces and logs (`[observability.otlp]`, off by default).
  - W3C trace context across requests, functions, queue messages, push webhooks and jobs.
  - The new `forgebase-alerts` crate: 14 built-in rules (queue backlog, dead letters, paused push,
    billing signature failures, 5xx ratio, disk, backup age, certificate expiry, …) and custom rules.
  - Silences, and notifiers for signed webhooks, Slack, email, PagerDuty and queue topics.
  - SLOs with multi-window burn-rate alerts.
- **Ops insights** ([ADR-0036](../adr/0036-ops-insights.md)): statement fingerprints with p50/p95/p99, a slow
  statement log and regression detection; per-tenant usage with cost estimates; function profiles with
  host-call timelines; audit search with CSV/JSONL export. Under `/api/v1/insights`.
- **Backup drills** ([ADR-0041](../adr/0041-backup-drills.md)): `forgebase backup drill` restores a backup into
  a scratch directory and starts a quiescent server on it. It checks counts, samples and keys, and reports
  RTO/RPO. Also a drill API with history and metrics, and an optional `[backup] drill_schedule`. Backups can
  carry the sealed `tls/` state (`[backup] include_tls`).
- **Runbooks**: [operations/](../operations/) covers HA failover, disaster recovery, every built-in alert,
  and upgrades.

### Data

- **Portable fuzzy search and openCypher** ([ADR-0034](../adr/0034-portable-fuzzy-and-cypher.md)): the `trigram`
  index kind and `fuzzy` work on SQLite and on PostgreSQL without pg_trgm. A read-only openCypher subset runs
  without Apache AGE. `GET /api/system/capabilities` lists which engine serves each feature. `db convert`
  carries trigram indexes in both directions.
- **Storage drivers** ([ADR-0040](../adr/0040-gcs-azure-storage.md)): native Google Cloud Storage and Azure Blob
  drivers. `[storage] signed_urls = "proxy" | "native" | "auto"` (default `proxy`) can hand out the
  provider's own download URLs (S3, GCS, Azure) after the same access checks.

### Webhooks and integrations

- **Webhook tooling** ([ADR-0031](../adr/0031-webhook-tooling.md)) for push subscriptions:
  - attempt log, test send, redrive and retry;
  - zero-downtime secret rotation (two `v1` signatures during the grace window);
  - endpoint health with optional auto-pause, and an event catalog;
  - `forgebase queues listen --forward-to` for local development.
- **Billing webhook inspector** ([ADR-0032](../adr/0032-billing-webhook-inspector.md)): every inbound provider
  webhook is recorded, with a budget for unverified ones. They can be replayed and re-verified.
- **More providers** ([ADR-0039](../adr/0039-more-providers.md)):
  - email via Resend, Postmark, SendGrid, Mailgun and SES;
  - SMS via Vonage, MessageBird/Bird, SNS and Plivo;
  - login presets for Microsoft Entra ID, GitLab, Slack, LinkedIn, Twitch, Bitbucket, Spotify and Keycloak.

### Developer workflow

- **Project as code** ([ADR-0037](../adr/0037-project-as-code.md)): `forgebase project pull|plan|apply|drift|validate`,
  `forgebase deploy` and `forgebase new` with CI templates.
- **Dev CLI** ([ADR-0038](../adr/0038-developer-workflow-cli.md)):
  - `forgebase dev`, an ephemeral emulator with `--seed` and `--watch`;
  - `forgebase gen types --lang ts|rust`;
  - `functions invoke --trace` and `functions logs --follow` with trace ids.
- **SDKs**:
  - JS and Rust now wrap every API, including the new ones.
  - New Dart/Flutter, Swift and Kotlin SDKs (`sdk/dart`, `sdk/swift`, `sdk/kotlin`).
  - Webhook signature helpers in JS, Rust and Kotlin.
- **Deployment**: a Helm chart (`deploy/helm/forgebase`, chart 0.2.0), Kustomize manifests (`deploy/kubernetes`)
  and a Terraform provider (`integrations/terraform-provider-forgebase`).
- **Dashboard**: new Alerts and Insights studios, a capability matrix, TLS and tracing cards, webhook tooling,
  a billing webhook inspector, provider forms, storage driver settings, and push subscription creation.
- **Benchmarks**: storage, graph, SQL and fuzzy benches; `fb-load` resource sampling and JSON output; a
  weekly Linux benchmark workflow ([benchmarks.md](../benchmarks.md) §9). See also
  [choosing-a-backend.md](../choosing-a-backend.md) and [capacity-planning.md](../capacity-planning.md).

### Upgrade notes

- **Migrations** 0050–0053, 0056 and 0058–0066 run at startup on both backends. They are forward-only, so
  snapshot first.
- **Embedders** (not the binary):
  - `forgebase_customize::MailProvider` and `forgebase_auth::SmsProvider` changed: sends return a receipt with
    the provider's message id.
  - `forgebase_backup::BackupSettings` is no longer `Copy`.
  - `BackupOptions` gained `include_tls`.
- **New config sections**, all optional: `[tls]`, `[observability]` (tracing plus the insight keys),
  `[alerts]`, and `[storage] signed_urls`. The CLI's client variables (`FORGEBASE_URL`, `FORGEBASE_TOKEN`, …)
  no longer stop `forgebase serve`.
- **Native signed URLs** bypass ForgeBase's metrics and limits, and uploads always use the proxy path
  (ADR-0040 §10).
- **Not yet verified on real infrastructure**:
  - timed Linux benchmarks;
  - Terraform acceptance runs;
  - a live Kubernetes cluster;
  - live-cloud runs of the storage drivers and email/SMS providers.

  Each is covered by mock, vector or schema tests.
