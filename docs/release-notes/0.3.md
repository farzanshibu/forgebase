# ForgeBase 0.3 release notes

## Upgrading to 0.3

PostgreSQL is now the default database. SQLite stays supported.

### What changed

- **New projects use PostgreSQL.** `forgebase init` asks (on a terminal)
  `Database: [1] PostgreSQL (default, bundled server) [2] SQLite (one file)`.
  Without a terminal it takes the build's default: PostgreSQL in the standard
  release, SQLite in the `-lite` release. Pass `--database postgres`,
  `--database sqlite` or `--database-url postgres://…` to decide.
- **The standard release embeds PostgreSQL 18.** The engine is unpacked into
  `<data_dir>/postgres/` on first start and runs as a child of
  `forgebase serve`. It listens on a Unix socket only; TCP is off unless you set
  `[database.postgres] listen`. The binary is larger by the engine (about 8 MB
  compressed).
- **`-lite` keeps the old footprint.** The `-lite` archives leave the engine
  out, default to SQLite, and print `lite: SQLite only, no bundled PostgreSQL`
  in `forgebase --version`. `init --database postgres` there needs your own
  server (`--database-url`).
- **PostgreSQL cannot run as root.** `init` as root with the bundled engine
  stops before writing anything: `PostgreSQL cannot run as root: run as an
  unprivileged user, or use --database sqlite`. There is no silent fallback.
  The Docker image already runs as an unprivileged user.
- **Docker.** The standard image initialises PostgreSQL by default. Give the
  container a larger `/dev/shm` (`shm_size`, see `docker-compose.yml`). The
  `-lite` image, or `FORGEBASE_DATABASE_BACKEND=sqlite`, keeps SQLite.

### Existing SQLite projects

Nothing switches on its own. At every start the data directory's backend
marker (`forgebase.backend`), or an existing `forgebase.db` when there is no
marker, wins over the default. After the upgrade:

- `forgebase serve` opens the same SQLite file as before.
- `forgebase status` and `forgebase doctor` print one line:
  `this project uses SQLite; PostgreSQL is the default now: forgebase db convert --to postgres moves it`.
  The System studio shows the same notice. The `-lite` release does not print it.
- A setting that contradicts the data directory (`backend = "postgres"` on a
  SQLite directory) stops startup and names `forgebase db convert`.

### Moving to PostgreSQL (optional)

1. `forgebase backup --label pre-0.3` and store `auth/master.key` safely.
2. Stop the server.
3. `forgebase db convert --to postgres` (`--help` lists the options). It
   takes a snapshot, copies every table, verifies the copy, writes the backend
   marker and `[database] backend`, and keeps the old file as
   `forgebase.db.pre-postgres`. A failed run leaves the SQLite project as it
   was.
4. Start the server. The project now reports `postgres-managed`.

To move back, `forgebase db convert --to sqlite`.

### Staying on SQLite

Nothing to do. The notice in `status` and `doctor` stays until you convert.
New SQLite projects: `forgebase init --database sqlite`, or use the `-lite`
release.
